Sign-in problems (Connect Cloud)

Cummins' login runs through Salesforce, which inspects how a client connects (its TLS fingerprint) and may refuse anything that isn't a real browser. If pairing failed with a message about being blocked, use a refresh token instead:

  1. On any computer, clone github.com/tebrown/cummins_hacs.
  2. Install its tools: pip install -r tools/requirements.txt then playwright install chromium.
  3. Run python tools/bootstrap_login.py with your CUMMINS_USERNAME and CUMMINS_PASSWORD set.
  4. Paste the printed refresh token into the password field when pairing (any e-mail address works).

Sessions expire eventually. When one does, the device becomes unavailable — use Repair on the device to sign in again.

Find the cloud start/stop endpoint (advanced)

Cummins' cloud command format has never been publicly documented, and the path this app tries first returns 404 not found. This tool asks the API which commands it advertises and then tests candidate endpoints to find the one that exists.

Nothing is started or stopped. Every test uses a deliberately invalid command name, so the generator can't act on it — a 404 means "no such endpoint", while any other response means the endpoint exists and simply rejected the fake command. That's the one we want.

      REMOTE or commands are ignored.
